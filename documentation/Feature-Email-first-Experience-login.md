# Feature: Email-first Experience Cloud login

### 1. Runtime Pattern

- Entry: unauthenticated visitor opens the Experience Cloud **Experience Builder** login page that hosts the **emailFirstLogin** LWC. The post-auth landing path is **hardcoded server-side to `/s/`**; no client-supplied redirect is accepted.
- Step A — Email + Next: LWC calls **`LoginRouterService.discover(email)`** (Guest context). Apex generates a **correlation id**, masks the identifier in logs, trims input, and rejects implausible input (**`type=NONE`**, no password step — indistinguishable from other blocked outcomes). If plausible, Apex queries **active User** where **Username** or **Email** equals the trimmed value (**`LIMIT 2`**). If **not exactly one** row, returns **`type=NONE`**. If **exactly one** user: loads **PermissionSetAssignment** marker strings (**`PermissionSet.Name`** and **`PermissionSet.Label`** for non-profile sets), queries **`Client_Sso_Routing__mdt`** for active **SAML** rows where `Permission_Set_Name__c` is in that set (highest **Priority__c**). If **no** qualifying CMDT row or **no** `Saml_Setting_Api_Name__c`, returns **`type=PASSWORD`**. If CMDT **does** define SAML: resolves **`SamlSsoConfig`** Id from optional **`Saml_Sso_Config_Id__c`** (Guest-safe) else from **`Saml_Setting_Api_Name__c`** (SOQL — often **no rows** for Guest), then builds SSO URL via **`Auth.AuthConfiguration.getSamlSsoUrl(communityBase, '/s/', samlConfigId)`** using **`Site.getBaseUrl()`**; if the URL is **non-blank**, returns **`type=SSO`** with **`redirectUrl`**; if the URL is **blank** (misconfiguration), returns **`type=PASSWORD`** so the member can still sign in with password while admins fix SAML (**WARN** debug logs `samlSetting` + `ssoUrlBlank=true`). Emits one **INFO** debug line per call (`route=SSO|PASSWORD|NONE` and optional SAML setting API name). On unexpected exceptions, **WARN** logs exception type + discover correlation id and returns **`type=NONE`**. LWC handling of **`discover`** outcomes is specified under **UI Contract** (**Next** result).
- Step B — Password + Sign in: LWC calls **`LoginRouterService.passwordLogin(email, password)`** (same first-step string). Apex resolves a **unique active User** by **Username** or **Email**, then calls **`Site.login`** with that user’s **`Username`**, **`password`**, and **`'/s/'`**. On success returns success + redirect URL string; on null or exception returns **generic** failure message (**Invalid username or password.**). Each attempt emits one **INFO** debug line (`email=<masked> success=<bool>`); unexpected exceptions add a **WARN** line with the exception type. LWC assigns **`window.location`** to returned URL on success.
- Invariants: no **`Site.passwordlessLogin`** with PASSWORD; no **`TwoFactorMethodsInfo`**; no client-supplied post-auth redirect (server-pinned to `/s/`); **no DML** on production login paths; **standard org users** who are **site members** use the same flow as partners.
- Failure handling: all **passwordLogin** failures use the same generic **`message`**; **discover** never returns “user not found.” **`PASSWORD`** advances the UI to the password step with no error line; **`NONE`**, transport errors, and other blocked outcomes on **Next** share the same client copy (**Something went wrong. Please try again.**). Exactly one user with CMDT SAML but a **blank** initiation URL still returns **`PASSWORD`** (availability fallback; **WARN** in Apex for ops).

### 2. UI Contract

- **Layout:** White background; **compact** outer padding (no full-viewport min-height). Centered card **`max-width: 480px`**, **`width: 100%`**, light gray border, slight radius, moderate inner padding—logo and header live in Experience Builder outside this component.
- **Modes:** (1) **Email** — **Email** field only, then centered **Next** (`neutral`). (2) **Password** — **Password** field, **Back** + **Sign in** (`neutral`).
- **First-step value:** Sent to Apex as the **discover** / **passwordLogin** identifier; it may match the member’s **`User.Email`** or **`User.Username`** (must uniquely resolve one active user for routing and for password sign-in). The field label is **Email**; Salesforce **`Site.login`** receives the stored **`Username`** after server-side resolution.
- **Footer (both steps):** Thin divider; **Forgot Your Password?** link (path: `/login` → `/ForgotPassword` swap, else `/s/ForgotPassword`).
- **Next (discover) result:** If **`type`** is **`SSO`** and **`redirectUrl`** is set → full-page navigation to IdP. If **`type`** is **`PASSWORD`** → switch to password mode with no error text. Otherwise (including **`NONE`**) → stay on the first mode and set error copy to **Something went wrong. Please try again.** (same copy as Apex/transport failure on **Next**).
- **Sign in (passwordLogin) result:** On failure, show Apex **`message`** if present, else **Invalid username or password.**; on transport/exception during **Sign in**, show **Something went wrong. Please try again.**
- **Buttons:** **Next** disabled while loading or when the email value is blank after trim; **Sign in** disabled while loading or when password is blank; **Back** disabled only while loading.
- **Errors:** Red **form-error** text (`role="alert"`) for the cases above; no static red instructional banners.
- **Loading:** Spinner inside card; loading disables the primary action buttons per the rules above.
- **Accessibility:** Labeled inputs; **`autocomplete="username"`** on the first field, **`autocomplete="current-password"`** on the password field.

### 3. System Components Involved

- **LoginRouterService** — Apex entrypoints for discover and password login; see [System-Components.md](System-Components.md).
- **Client_Sso_Routing__mdt** — CMDT routing table; see [System-Components.md](System-Components.md).
- **emailFirstLogin** — Experience login LWC; target **`lightningCommunity__Page`** (place on the site **Login** page in Experience Builder); see [System-Components.md](System-Components.md).
- **Login_Router_Guest** permission set — grants Apex class access to Guest; object/FLS completed in org per security review.

For Salesforce’s documented **`Auth.LoginDiscoveryHandler`** alternative (vs Guest **`discover`**), see [Login-discovery-handler-option.md](Login-discovery-handler-option.md) — not a shipped component of this feature.
